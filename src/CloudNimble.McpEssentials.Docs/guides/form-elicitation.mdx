MCP form elicitation asks the client for a **flat object of primitives**. Build the schema once at startup with [`FormElicitationBuilder`](/api-reference/CloudNimble/McpEssentials/Core/Tasks/Elicitations/FormElicitationBuilder), register it with [`AddFormElicitation`](/api-reference/Microsoft/Extensions/DependencyInjection/IServiceCollection), and send it with [`server.ElicitAsync("ship")`](/api-reference/ModelContextProtocol/Server/McpServer). When the tool is running as an MCP task, the SDK interceptor parks the form on the task for you.

<CardGroup cols={3}>
  <Card title="Register at startup" icon="bookmark">
    `AddFormElicitation("ship", form)` is a keyed singleton, the same idea as a named `HttpClient`.
  </Card>
  <Card title="Elicit by name" icon="paper-plane">
    `await server.ElicitAsync("ship")` resolves the form from `McpServer.Services`.
  </Card>
  <Card title="Parked on a task" icon="pause">
    Awaiting `ElicitAsync` inside an MCP task lets the SDK interceptor park the form. The tool continues when the client answers.
  </Card>
</CardGroup>

## Register a named form

<Steps>
  <Step title="Build the form">
    Field by field, `From<T>()`, or a loop over metadata. The last node on the chain is still a valid form.

    ```csharp
    var form = FormElicitationBuilder.Create("Ship this order")
        .String("trackingNumber").Required();
    ```
  </Step>
  <Step title="Register it">
    [`AddFormElicitation`](/api-reference/Microsoft/Extensions/DependencyInjection/IServiceCollection) stamps `Name` when it is empty so the keyed singleton matches the registration name.

    ```csharp
    services.AddFormElicitation("ship", form);
    ```
  </Step>
  <Step title="Elicit by name">
    The tool does not hold a reference to the builder. The server resolves the keyed singleton and sends it.

    ```csharp
    [McpServerTool(Name = "ShipOrder"), Description("Asks for a tracking number, then ships.")]
    public static async Task<string> ShipOrder(McpServer server, CancellationToken cancellationToken)
    {
        var result = await server.ElicitAsync("ship", cancellationToken);
        if (!result.IsAccepted)
        {
            return "cancelled";
        }

        return $"Shipped as {result.Content!["trackingNumber"].GetString()}.";
    }
    ```
  </Step>
</Steps>

<Tip>
`Create`, `From<T>`, and every field facade implement [`IFormElicitationSource`](/api-reference/CloudNimble/McpEssentials/Core/Tasks/Elicitations/IFormElicitationSource). The current node on the chain is a valid argument to `AddFormElicitation`, `ElicitAsync`, and `SetInputRequestsAsync`.
</Tip>

## Pick an authoring style

<Tabs>
  <Tab title="Field by field" icon="keyboard">
    Start empty and add fields by wire name. Keep the builder when you add several fields in a loop.

    ```csharp
    var result = await server.ElicitAsync(
        FormElicitationBuilder.Create("Tell us who you are")
            .String("firstName").Required().MinLength(1)
            .Email("email").Required()
            .Integer("age").Between(18, 120),
        cancellationToken);

    if (!result.IsAccepted)
    {
        return "cancelled";
    }

    var name = result.Content!["firstName"].GetString();
    ```
  </Tab>
  <Tab title="From a type" icon="cube">
    Seed from a DTO, then override titles, bounds, and required. `T` is inferred on `ElicitAsync`.

    ```csharp
    public class ProductQuery
    {
        public string? Filter { get; set; }
        public int Top { get; set; }
        public int Skip { get; set; }
    }

    var result = await server.ElicitAsync(
        FormElicitationBuilder.From<ProductQuery>("Query products")
            .Exclude(x => x.Skip)
            .Integer(x => x.Top).Min(1).Max(1000).Default(20),
        cancellationToken);

    if (result.IsAccepted)
    {
        Query(result.Content!);
    }
    ```
  </Tab>
  <Tab title="Metadata-driven" icon="diagram-project">
    Keep the builder. Add a field per runtime name (EDM property, query option, action parameter). Bind accepted content onto a DTO if you have one.

    ```csharp
    var form = FormElicitationBuilder.Create($"How should we query {entitySet}?");
    form.String("filter").Title("$filter").Description("OData filter expression");
    form.Integer("top").Title("$top").Min(1).Max(1000).Default(20);

    var result = await server.ElicitAsync<ProductQuery>(form, cancellationToken);
    if (result.IsAccepted)
    {
        Query(result.Content!);
    }
    ```
  </Tab>
</Tabs>

## Start a form

<CodeGroup>

```csharp Create
var form = FormElicitationBuilder.Create("Need a shipping address");
```

```csharp From a type
var form = FormElicitationBuilder.From<CheckoutForm>("Confirm checkout");
```

```csharp Confirm dialog
var result = await server.ElicitAsync(
    FormElicitationBuilder.From<EmptyForm>("Delete this order?"),
    cancellationToken);
```

</CodeGroup>

`From<T>().Build()` with no chain is a valid form. Zero fields is a confirm dialog: the client shows the message and accept / decline.

`Create(null)` and `From<T>(null)` throw `ArgumentNullException`. Whitespace messages are allowed at create and throw from `Build()`.

## Field kinds

Starters camelCase the name (`FirstName` → `firstName`) and Titleize the label (`TimeToLive` → `"Time To Live"`). `.Title(...)` overrides the label.

<AccordionGroup>
  <Accordion title="String, email, URI, date" icon="font">
    ```csharp
    form.String("notes").MinLength(1).MaxLength(400).Default("n/a");
    form.Email("email").Required();
    form.Uri("homepage");
    form.Date("birthday");       // format date
    form.DateTime("startsAt");   // format date-time
    ```

    `String` after `Email` on the same name clears the format. `Email` / `Uri` / `Date` / `DateTime` on an existing string field set the format in place.
  </Accordion>
  <Accordion title="Integer and number" icon="hashtag">
    ```csharp
    form.Integer("age").Min(0).Max(130).Default(42);
    form.Number("price").Between(0.5, 99.9);
    ```

    `Between` throws immediately when min &gt; max. Setting `Min` then `Max` inverted throws from `Build()`.
  </Accordion>
  <Accordion title="Boolean" icon="toggle-on">
    ```csharp
    form.Boolean("subscribe").Default(true).Optional();
    ```
  </Accordion>
  <Accordion title="Single-select and multi-select" icon="list-check">
    Untitled options emit `enum`. Any titled option emits `oneOf` / `anyOf` with `const` + `title`.

    <CodeGroup>

    ```csharp Untitled
    form.Choice("color")
        .Option("red")
        .Option("blue")
        .Default("red");
    ```

    ```csharp Titled
    form.Choice("color")
        .Option("red", "Crimson")
        .Option("blue", "Blue")
        .Default("red");
    ```

    ```csharp Multi-select
    form.MultiChoice("roles")
        .Option("admin", "Administrator")
        .Option("user", "User")
        .MinItems(1)
        .MaxItems(2)
        .Default("user");
    ```

    </CodeGroup>

    Duplicate option values throw immediately. An empty option list throws from `Build()`. A default that is not in the list throws from `Build()`.
  </Accordion>
</AccordionGroup>

## Required vs optional

<Tabs>
  <Tab title="C# nullability" icon="code">
    Non-nullable properties and the `required` keyword seed as required. `string?` and `int?` seed as optional. `.Required()` / `.Optional()` override after seed.

    ```csharp
    public class SignupForm
    {
        public required string Code { get; set; }
        public required string? Note { get; set; } // still required
        public string? Hint { get; set; }          // optional
        public int Age { get; set; }               // required
        public int? Score { get; set; }            // optional
    }
    ```
  </Tab>
  <Tab title="Fluent override" icon="sliders">
    ```csharp
    FormElicitationBuilder.From<SignupForm>("Sign up")
        .String(x => x.Code).Optional()
        .String(x => x.Hint).Required();
    ```
  </Tab>
</Tabs>

## From a type

`From<T>()` walks public instance readable properties. Unmappable members are skipped. Two properties that camelCase to the same wire name throw.

<AccordionGroup>
  <Accordion title="What maps" icon="check">
    | CLR | Field |
    |---|---|
    | `string`, `Guid`, `char` | string |
    | `Uri` | string, format `uri` |
    | `DateOnly` | string, format `date` |
    | `DateTime`, `DateTimeOffset` | string, format `date-time` |
    | `bool` | boolean |
    | integer types (`byte` … `ulong`) | integer |
    | `float`, `double`, `decimal` | number |
    | enum | single-select (titled from the member names) |
    | `[Flags]` enum, `TEnum[]`, `IEnumerable<TEnum>` | multi-select |
  </Accordion>
  <Accordion title="What is skipped" icon="ban">
    Nested objects, `Dictionary<,>`, `object`, `TimeSpan`, `byte[]`, `string[]`, `int[]`, indexers, write-only properties, static properties. `Exclude` of a skipped member is a successful no-op.
  </Accordion>
  <Accordion title="Reconfigure and extra fields" icon="pen">
    ```csharp
    FormElicitationBuilder.From<KitchenSinkForm>("Fill this out")
        .Exclude(x => x.Nickname)
        .String(x => x.Name).Title("Full name").MinLength(1)
        .Email(x => x.Homepage)          // reconfigure a seeded URI as email
        .Integer("extraCount").Min(0);   // extra string-named field
    ```

    Calling a starter for an existing name updates that field in place. A different kind resets kind-specific constraints and keeps name, title, description, and required.
  </Accordion>
</AccordionGroup>

## Send the form

<Tabs>
  <Tab title="By name" icon="bookmark">
    Resolve the form registered at startup. This is the usual call from a tool.

    ```csharp
    var result = await server.ElicitAsync("ship", cancellationToken);
    ```

    Bind accepted content onto a DTO after the untyped round-trip:

    ```csharp
    var raw = await server.ElicitAsync("query", cancellationToken);
    var typed = FormElicitationBuilder<ProductQuery>.Bind(raw);
    ```
  </Tab>
  <Tab title="Untyped instance" icon="brackets-curly">
    Pass a builder or facade when you did not register a name. Content is `IDictionary<string, JsonElement>` keyed by camelCase wire names.

    ```csharp
    var result = await server.ElicitAsync(
        FormElicitationBuilder.Create("Need a name").String("name").Required(),
        cancellationToken);

    if (result.IsAccepted)
    {
        var name = result.Content!["name"].GetString();
    }
    ```
  </Tab>
  <Tab title="Typed From&lt;T&gt;" icon="cube">
    `T` is inferred. Cancel and decline leave `Content` default.

    ```csharp
    var result = await server.ElicitAsync(
        FormElicitationBuilder.From<ProductQuery>("Query products"),
        cancellationToken);

    if (result.IsAccepted)
    {
        Use(result.Content!);
    }
    ```
  </Tab>
  <Tab title="Bind later" icon="link">
    Specify `T` when the form was built from strings.

    ```csharp
    var result = await server.ElicitAsync<ProductQuery>(form, cancellationToken);
    ```

    Or bind after an untyped round-trip:

    ```csharp
    var typed = FormElicitationBuilder<ProductQuery>.Bind(raw);
    ```
  </Tab>
</Tabs>

Wire names are camelCase. Enum members match `Enum.GetNames` (`BlueGreen`, not `blueGreen`). Native AOT callers pass `JsonSerializerOptions` from a `JsonSerializerContext`:

```csharp
var result = await server.ElicitAsync<ProductQuery>(
    form,
    ProductQueryJsonContext.Default.Options,
    cancellationToken);
```

## Streamable HTTP

McpEssentials hosts Streamable HTTP with `Stateless = true` on the current spec revision (`2026-07-28`). Call the `McpServer` from the tool parameter or `RequestContext`.

A non-task tool throws [`InputRequiredException`](https://csharp.sdk.modelcontextprotocol.io/concepts/mrtr) with the form as an `InputRequest`. The handler returns. The client retries `tools/call` with `inputResponses`. There is no in-process waiter.

SDK `ElicitAsync` without a task interceptor throws `InvalidOperationException("Elicitation is not supported in stateless mode.")`. `WithTasks` installs `OutgoingRequestInterceptor` for that invocation, parks `InputRequest.ForElicitation` on the task, and completes when `InputResponseReceived` fires.

```csharp
[McpServerTool(Name = "ShipOrder"), Description("Asks for a tracking number, then ships.")]
public static string ShipOrder(McpServer server, RequestContext<CallToolRequestParams> context)
{
    if (context.Params?.InputResponses?.TryGetValue("ship", out var response) is true)
    {
        var result = response.Deserialize(InputResponse.ElicitResultJsonTypeInfo);
        if (result?.IsAccepted is not true)
        {
            return "cancelled";
        }

        return $"Shipped as {result.Content!["trackingNumber"].GetString()}.";
    }

    if (!server.IsMrtrSupported)
    {
        return "This tool needs a 2026-07-28 client, or a task-backed call.";
    }

    var form = server.Services!.GetRequiredKeyedService<IFormElicitationSource>("ship");
    throw new InputRequiredException(
        new Dictionary<string, InputRequest> { ["ship"] = form.ToInputRequest() },
        requestState: "ship");
}
```

## Tasks

A tool that `await`s `server.ElicitAsync(form)` inside a task **does not call the store**. The SDK interceptor writes the form as an [`InputRequest`](/api-reference/ModelContextProtocol/Extensions/Tasks/IMcpTaskStore) and resumes when the client responds.

<Steps>
  <Step title="Tool awaits ElicitAsync">
    Same call as a non-task tool. Use the `McpServer` from the request context so the interceptor is the one `WithTasks` installed on that invocation.
  </Step>
  <Step title="Interceptor parks the form">
    The task moves to `InputRequired`. The originating HTTP POST already returned `CreateTaskResult`. The client polls `tasks/get` and fulfills the elicitation with `tasks/update`.
  </Step>
  <Step title="Client responds">
    `InputResponseReceived` completes the await. Bind or read `result.Content` and continue the tool.
  </Step>
</Steps>

<Note>
The await is a `ValueTask` parked on `InputResponseReceived`. It does not occupy a thread, and it does not hold the HTTP POST. A durable store keeps the task row; it does not serialize the paused method. Process recycle, `ttlMs`, `tasks/cancel`, and a `tasks/update` that never reaches this process all end the wait. A user who is gone for days is a store TTL and an in-process continuation problem, not an open request.
</Note>

Park a form yourself from a background worker or when you need a stable request id:

<CodeGroup>

```csharp Generated id
await store.SetInputRequestsAsync(taskId, form);
```

```csharp Explicit id
await store.SetInputRequestsAsync(taskId, "create-product", form);
```

```csharp InputRequest
await store.SetInputRequestsAsync(taskId, form.ToInputRequest());
```

</CodeGroup>

`ToInputRequest()` is the same payload `ElicitAsync` sends. Omit the request id to get a 32-character hex key.

## Compact XML for OData

OData `$metadata` can wrap a registered form as an `Mcp.ElicitForm` island. That codec is `ToXml()` / `ParseXml` on the builder. MCP elicitation on the wire does not use it: `ElicitAsync` calls `Build()` and sends SDK `ElicitRequestParams` (`mode: form`).

```csharp
string xml = form.ToXml();
var again = FormElicitationBuilder.ParseXml(xml);
```

`ToXml()` caches the island on the builder so a named DI singleton does not rewrite it. `ParseXml` / `FromDefinition` rebuild an untyped builder. Adding a field after `Build` / `ToXml` / `ToJson` / `ToDefinition` / `ToInputRequest` throws; the analyzer reports **MCPESS006**.

The codec is handwritten `XmlWriter` / `XmlReader` (AOT-safe). See `specs/form-xml.md`.

## Validation that throws

These fail at the fluent call or at `Build()` / `ElicitAsync` / `SetInputRequestsAsync`, not after the client answers.

| When | Exception |
|---|---|
| Empty or whitespace field name | `ArgumentException` |
| Negative `MinLength` / `MaxLength` / `MinItems` / `MaxItems` | `ArgumentOutOfRangeException` |
| `Between` with min &gt; max | `ArgumentException` |
| Duplicate option value | `InvalidOperationException` |
| Empty option value or titled option with blank title | `ArgumentException` |
| Whitespace message at `Build` | `InvalidOperationException` |
| Choice with no options | `InvalidOperationException` |
| Default not in the option list | `InvalidOperationException` |
| `minLength` &gt; `maxLength` (or min/max, minItems/maxItems) at `Build` | `InvalidOperationException` |
| Two `From<T>` properties that camelCase to the same name | `InvalidOperationException` |

<Note>
An empty property list is legal. Nested property access in `Exclude` / expression starters (`x => x.Address.City`) throws `ArgumentException`.
</Note>
