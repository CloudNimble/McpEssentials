Core ships the in-memory store. Everything else is a provider that subclasses `AuthenticatedMcpTaskStoreBase` and implements `IPerUserMcpTaskStore` with the same current-user callback, `RequireUserId`, and `IsOwnedBy` rules.

The full design lives in [`specs/authenticated-task-stores.md`](https://github.com/CloudNimble/McpEssentials/blob/main/specs/authenticated-task-stores.md). This page is the map.

## Shared contract

Every provider:

- Registers as a **singleton** `IMcpTaskStore`.
- Stamps `OwnerUserId` on `CreateTaskAsync` and does not return until a later `GetTaskAsync` can see that row (SEP-2663 §306).
- Isolates `Get` / `Cancel` / `ResolveInputRequests` to the current user.
- Lets `SetCompleted` / `SetFailed` / `SetInputRequests` run without a live HTTP user.
- Raises `InputResponseReceived` after persisting a resolved input, including across nodes (pub/sub, NOTIFY, change feed).
- Treats terminal transitions as idempotent no-ops.
- Honors TTL with a sweep or native expiry.

Recommended row:

| Column | Role |
|---|---|
| `TaskId` | Primary key (SDK-generated id) |
| `OwnerUserId` | Isolation key; index `(OwnerUserId, TaskId)` |
| `Status` | `working` / `input_required` / `completed` / `cancelled` / `failed` |
| `CreatedAt` / `LastUpdatedAt` | UTC |
| `TimeToLive` / `ExpiresAt` | Sweep or native TTL |
| `PollIntervalMs` / `StatusMessage` | Protocol metadata |
| `ResultJson` / `ErrorJson` | Terminal payloads |
| `InputRequestsJson` | Outstanding input map |

## Packages

| Package | Engine | Fan-out for `InputResponseReceived` | When to use |
|---|---|---|---|
| `McpEssentials.Core` | In-memory | In-process event | Single process, tests, local |
| `McpEssentials.EntityFrameworkCore` | Any EF Core provider | Optional: none, or host-supplied bus | SQL Server / SQLite / PostgreSQL / Cosmos via EF |
| `McpEssentials.PostgreSQL` | Npgsql | `LISTEN` / `NOTIFY` | Native Postgres, multi-node |
| `McpEssentials.SqlServer` | Microsoft.Data.SqlClient | Query Notifications or Service Broker | Azure SQL / SQL Server without EF |
| `McpEssentials.Redis` | StackExchange.Redis | Redis pub/sub | Low-latency, native TTL |
| `McpEssentials.DistributedCache` | `IDistributedCache` | Host-supplied bus | Already on Redis/NCache/SQL cache |
| `McpEssentials.Cosmos` | Azure Cosmos DB | Change feed | Partition by `OwnerUserId` |
| `McpEssentials.MongoDB` | MongoDB | Change streams | Document hosts |
| `McpEssentials.Nats` | NATS JetStream | Core NATS subjects | Edge / KV + signals |
| `McpEssentials.AzureTables` | Azure Table Storage | Queue or Service Bus | Cheap point reads |

EF Core is the default durable package: one implementation, many databases. The native PostgreSQL and Redis packages exist when you need LISTEN/NOTIFY or pub/sub without an extra bus.

## Host swap

HTTP identity stays on the platform accessor. Development uses Core's in-memory store. Production registers a durable store with the same factory; the provider package registers `IMcpTaskStore` and enables Tasks.

```csharp
builder.Services.AddHttpContextAccessor();

Func<IServiceProvider, ClaimsPrincipal?> currentUser =
    sp => sp.GetRequiredService<IHttpContextAccessor>().HttpContext?.User;

// Development
builder.Services.AddMcpServer()
    .WithHttpTransport(o => o.Stateless = true)
    .WithAuthenticatedTasks(currentUser);

// Production (once the provider package exists)
builder.Services.AddMcpEssentialsEntityFrameworkTasks<AppDbContext>(currentUser);
builder.Services.AddMcpServer()
    .WithHttpTransport(o => o.Stateless = true);
```

Provider packages take `Func<IServiceProvider, ClaimsPrincipal?>` so they resolve `IHttpContextAccessor` (or any other registered identity source) from the built provider. Isolation helpers stay in Core. Providers depend on `McpEssentials.Core`, not on each other.

The in-memory path is in [`samples/CloudNimble.McpEssentials.Samples.Web`](https://github.com/CloudNimble/McpEssentials/tree/main/samples/CloudNimble.McpEssentials.Samples.Web). See [Authenticated tasks](/guides/authenticated-tasks) for the overloads.
